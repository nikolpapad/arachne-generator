# Handoff: method C (trained neural network)

**Status (2026-10-25): not started. Planning notes only.**
No model code exists yet, and no motif has been counted yet, so whether C is
viable is still **unknown**. Read section 2 before writing any code.

Read first: `README.md` and `docs/motif-counting-guide.md` (the counting step
and how the catalog data works).

---

## 1. Goal

A web page where the user drags a path on an empty grid and gets a new filet
crochet pattern drawn along/around that path, **learned from the real Arachne
catalog**.

Method C = a **conditional generative model per motif**:
input a **path mask**, output a **stitch grid** of that motif following the
path.

Hard requirements (from the project owner):
- **Learned from the real catalog.** Nothing invented or procedural.
- **No plain copy-paste** of existing patterns. Outputs must be checked for
  this (section 6).
- **Output format** `{w, h, rows, palette}` so it imports back into Arachne
  Studio. Mind the polarity (section 3).
- Simple, readable code. The owner dislikes over-engineering and is learning,
  so explain choices in plain language.

---

## 2. Gate: only start C for a motif with ≥ ~200 examples

C is only worth trying for a motif with roughly **200+ patterns** ticked "yes".
With fewer, use method B (cut and place real motifs).

To check:
```bash
cd ~/arachne-generator && .venv/bin/python catalog/count.py
```
The list of examples for motif `X` is every key in `tags.json` whose value
contains `"X"`.

**Never assume a count.** If `tags.json` is empty or the motif is under 200,
stop and tell the owner. Don't invent data or pad the set with similar-looking
motifs without asking.

## 3. Data facts you must know

| Fact | Detail |
|---|---|
| Location | `data/previews/` → link to `~/pattern-app/apps/api/assets/previews/`; `<id>_grid.json` + `<id>_preview.png` |
| Size | 2506 files; **2283 unique** after removing identical copies (book 009 = re-scan of 003) and 14 grids under 10 cells on a side |
| Format | `{"w", "h", "rows": ["0101…", …]}`. `palette` is **missing in all files** (null) |
| **Polarity** | `"1"` = stitched ground, `"0"` = motif **and** the empty outside of shaped pieces. The opposite of the original spec. |
| Motif mask | `catalog/load.py: motif_mask(grid)` → True = motif cell. Checked on 60+ patterns, including large ones. **Reuse it; don't re-derive.** |
| Grid sizes | 10 to 982 cells per side, median about 68×57. ~190 patterns have a side over 300 |
| Content | Many patterns are scenes with several motifs. Shapes include rectangles, triangles (corners), rounds and long edging strips |
| Duplicates | `catalog/duplicates.json` (generated by `embed.py`) |

**Export polarity:** to write a generated pattern back for Arachne Studio,
convert *motif mask → catalog convention*: motif cells = `"0"`, ground =
`"1"`. Check with the owner how the site renders "outside" cells for shaped
pieces before deciding what to put there.

Reusable helpers in `catalog/load.py`: `all_ids()`, `load_grid(id)`,
`motif_mask(grid)`, `outside_mask(grid)`, `grid_hash(grid)`,
`render(mask, size)`.

## 4. Proposed pipeline

These are proposals to discuss with the owner, not decisions.

### 4.1 Locate the motif inside each "yes" pattern

A tag says *the pattern contains* a putto, not *where*. Training needs the
motif cut out.

- **Suggested approach:** reuse the CLIP crops from `embed.py`. For each "yes"
  pattern, the crop with the highest similarity to the motif query is a good
  candidate box. Show the candidates in a small review page, modelled on
  `search.html`, where the owner accepts, adjusts or rejects each box. Save
  the result to `motif_boxes.json`:
  `{"<pattern_id>": [[y, x, h, w], …]}` (one pattern may hold several).
- Then cut the motif mask inside each box, and separate touching motifs by
  connected components where possible.
- **Don't** accept boxes automatically without review. Many patterns are
  crowded scenes.

### 4.2 Build (path → motif) training pairs automatically

For each cut-out motif:
1. **Skeletonize** the motif mask, thinning it to 1-cell-wide lines. Keep the
   longest path through the skeleton as "the path a user would have drawn".
   `scikit-image` (`skeletonize`) would be a new dependency, so ask first, or
   write a small numpy thinning.
2. Rasterise that path into a mask the same size as the motif.
3. A training pair is *(path mask, motif mask)*.

**Augmentation**, because ~200 examples is small:
- horizontal flip, and vertical flip if the motif allows it (a putto
  upside-down may not be valid, so ask)
- small shifts
- integer scaling (×2 nearest-neighbour), or resampling to a few fixed sizes
- several path variants per motif (different skeleton branches, slight
  smoothing)

### 4.3 Model options, simplest first

| Option | What it is | Pros | Cons |
|---|---|---|---|
| **pix2pix-style conditional U-Net** | Image-to-image network: path mask in, motif mask out (binary, sigmoid output). Optional small discriminator (GAN) for sharper output | Simple, fast to train, well known | Tends to average and blur with few examples, and may memorise |
| **Conditional diffusion (small)** | Learns to remove noise from motif grids, guided by the path mask | Best output quality and variety | Slower to train and run, more code |
| **Masked-token transformer** | Treat cells as tokens and predict hidden cells given the path | Natural fit for discrete stitches | More engineering |

**Suggested start:** a small conditional U-Net on fixed-size grids (e.g.
64×64), trained on one motif, to learn quickly whether 200 examples are
enough. Move to diffusion only if the U-Net output is promising but too
blurry or repetitive.

**Pretraining idea:** first train the network on **all 2283 patterns** without
tags, by hiding a region and asking it to fill it in (self-supervised
inpainting), then fine-tune on the motif pairs. This uses the whole catalog
to learn "what filet looks like" and reduces how much motif data is needed.

### 4.4 Output post-processing

- Threshold to binary (0/1).
- Optionally remove isolated single cells or tiny specks that wouldn't
  crochet well. Ask the owner what is acceptable in filet.
- Place the generated motif onto the user's canvas; method A (texture fill)
  can fill the rest later.

  **Ask before adding** anything else (scikit-image, diffusers, lightning…).

## 6. Evaluation: how to know it works

1. **Not a copy.** For each generated motif, find its nearest neighbour in
   the training set (Hamming distance on aligned grids, or CLIP similarity
   of the rendered image) and show them side by side. Flag outputs that are
   near-identical. This is the owner's "no plain copy-paste" requirement, so
   make it a standard report, not an afterthought.
2. **Looks like the motif.** Render outputs with `load.render()` in a review
   sheet and let the owner judge. Optionally score each with CLIP against the
   motif phrasings.
3. **Follows the path.** Measure how much of the path is covered by the
   motif.
4. **Held-out check.** Keep ~10% of motifs out of training, and compare
   generated outputs for their paths with the real ones.

Review by eye is essential. The motif-mask work showed that rules which look
fine on average can fail badly on specific patterns.

## 9. Pitfalls already learned

- **Polarity:** `"1"` is ground. Always use `motif_mask()`, never raw `"1"`
  cells.
- **Duplicates:** don't let a 003/009 duplicate pair end up split across
  train and test. Use `grid_hash()` to dedupe.
- **Big scenes:** motifs inside 300–900-cell scenes are small. Crop to the
  motif; never train on whole scenes resized down.
- **Shapes:** outside areas of triangles and rounds are not ground. Exclude
  them via `outside_mask()`.
- **Don't trust the first idea about the data. Render it and look.**
